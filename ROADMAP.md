Status: living document · Last updated: 2026-10-26

## 1. How this file works

- **Task IDs** are `T-xxx`. Each task (except `T-000`) gets a folder `features/T-xxx-<slug>/` with `requirements.md`, `plan.md`, and `validation.md`, created from `features/_templates/` when the task starts (`sdd feature new T-xxx <slug>`).
- **Statuses:** `Not started` → `Specifying` → `Awaiting plan approval` → `Implementing` → `Awaiting review` → `Done`. Also `Blocked (<reason>)`.
- **Gates:** the human replies `APPROVED T-xxx` (GATE 1, before any code) and `COMMITTED T-xxx` (GATE 2, after reviewing and committing). See the agent contract.
- **One task at a time.** Work discovered along the way goes to the Parking lot, not into the current task.
- **Decisions** listed per task (D-xxx) must be Approved in the Decision register at that task's GATE 1.
- Task cells must not contain a literal pipe character.

## 5. Unknown-technology protocol (spikes)

Unfamiliar technology derails projects. To prevent that:

- Anything unfamiliar gets a **time-boxed spike** first (one sitting). Output is notes and a decision, not production code.
- Spike code is disposable: it lives under `features/T-xxx-<slug>/spike/` and is never imported by production code.
- Spikes follow the same gates as any task.
- Record what you learned in `SKILLS.md` (human skill map and pitfalls log).

## 6. Scope-cut order if behind schedule

1. Defer T-004 (adopt).
2. Defer T-003 (upgrade).
3. Never cut: the never-overwrite guarantees (S1), `sdd check`, and the verification on a real Mac (T-002).
